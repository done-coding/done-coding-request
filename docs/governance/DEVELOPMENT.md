# 项目开发模式

> 文档定位：规范 · 适用于本项目所有目录的开发任务，由项目根 AGENTS.md 要求读取。

## 领域与批次

- **领域划分**：一项能力的全部技术落点组成一个领域，领域是最小交付单位；其前后端、CLI、SDK 等落点一起交付，[MUST NOT] 按技术层拆任务。
- **批次单**：一张单含 N 个领域，一张单 = 一个会话 = 一次交付。单领域批次只是 N=1，[MUST NOT] 据此设置常驻「领域会话」。
- **批次串**：一个窗口串行做完的几批，每批任务表末项写「交付后立即开始下一批 `<id>`」，串末写收工。接到串首 id 就做到串末。

## 执行与进度

- 承接批次时，需求正文、所涉领域快照和契约是执行依据。能从这些材料与代码中核实、推导的细节 [MUST] 自行补齐。
- 进度 [MUST] 随手写进本批次 `PROGRESS.md`，让上下文压缩后的会话能从文件恢复。
- 上下文压缩、会话恢复或跨工具接手后，[MUST] 重读适用的根指令、本文件、本批 `PROGRESS.md` 和未完成条目；按需核对所涉领域快照、契约、实际产物与 git 状态。[MUST NOT] 只凭压缩摘要宣称完成。
- 用户在执行中插问或纠正，简答并纳入本批目标后继续已授权工作；只有明确取消或不兼容的新目标才替换任务。咨询不自动授权改动，建议、已执行、已验证和未完成项分别说明。
- 只有不同理解会导致实质不同的实现，且读遍相关代码、快照、契约和 git 后仍判不定时，才就该处提问。

## 停止与交付条件

ⓐ **缺权限**：破坏性写、不可逆动作、push 或扩大对外暴露面，且缺少本次执行许可。授权在册不等于本次执行许可。
ⓑ **前提不成立**：需求前提已被证据否定，或与既有契约冲突；[MUST] 带证据报告。
ⓒ **缺资源**：缺少自行无法取得的凭据、环境或外部服务。
ⓓ **交付完成**：未完成条目已回池、所涉领域快照已更新、批次已归档、快照改动不晚于归档 commit、清单重生成零 diff。刷新快照须在本批 PROGRESS 说明替换的旧事实及移出历史的固定落点，快照正文只保留当前事实。

WHEN 用户限定只读、系统事实未变且报告就是交付物：PROGRESS 记录“事实未变、报告即交付物”、事实核验依据、报告路径与交付 sha；以该核验替代快照 diff，不越权改已有快照。报告与证据按项目固定落点封存，以稳定 ID / 主题索引检索；发现需修订的事实或待实施建议如实记未完成，按授权回池。理由与实测：只读审计 m6r8kt 的交付物是报告，硬凑快照改动会超出范围。

除以上情形外，[MUST] 持续推进当前已授权批次；[MUST NOT] 用半成品汇报或「是否继续」代替执行。
